PLAN DE DISTRIBUCIÓN "PARA CUALQUIERA" — dedalo
================================================================================
Objetivo: que CUALQUIER usuario (no técnico), en sistemas MODERNOS y SIN FIRMA
de código, pueda descargar, instalar y usar la app. Se descartan a propósito
sistemas viejos (glibc antigua, ARM Linux, etc.).

Decisiones cerradas:
  · Sin firma de código (se aceptan avisos SmartScreen/Gatekeeper/AppImage).
  · Solo binarios sobre glibc moderna (build en Ubuntu-latest).
  · Gate sin dependencia de Git en Windows -> port a Python, MANTENIENDO gate.sh.
  · gate.py es el MOTOR ÚNICO del loop (delega a bash para checks .sh si existe).
  · Windows: instalador .exe (Inno Setup) + .zip portátil.
  · Auto-actualización: comprobar y avisar (no aplicar).
  · Linux: NO añadir .rpm/Flatpak/Snap. Debian/Ubuntu usan .deb; el resto de
    distros se arreglan con el .AppImage. Punto.

FASE 1a — GATE PORTABLE SIN GIT (lo grande)
--------------------------------------------------------------------------------
Problema: en Windows sin Git Bash, el gate (bash) falla y BLOQUEA cada tarea.
Solución: motor de gate en Python, manteniendo gate.sh para back-compat.

- dedalo/gate.py (nuevo, orquestador):
    · Descubre checks por prefijo numérico en gate_checks/.
    · Ejecuta *.py nativamente; *.sh vía bash SOLO si bash existe.
    · Conserva contrato: [GATE] ✓/✗, rc 0=todo OK / 1=algún fallo,
      avisos ⚠ no bloqueantes. Mismo parseo que usa loop.py.
- dedalo/gate_env.py (nuevo): equivalente Python de _env.sh.
    · Detecta BACKEND_DIR, FRONTEND_DIR, PY_BACKEND, PY_FRONTEND.
    · Comandos por defecto como LISTAS argv (sin shell); overrides del usuario
      se ejecutan con el shell del SO.
    · Autodetección Django / Python genérico + endpoints.txt.
- Checks por defecto en Python, en dedalo/plantillas_data/gate_checks/:
    01_db.py, 02_migrations.py, 03_backend.py (urllib, sin curl),
    04_imports.py, 05_tests.py, 98_criterio.py (juez IA), 99_custom.py (ruff).
- loop.py: invocar `python -m dedalo.gate` como subproceso
    (mismo GATE_TIMEOUT/contrato). gate.sh y los .sh siguen copiándose y
    sirviendo en Unix/manual.
- Tests: tests/test_gate_py.py replicando tests/test_gate.py
    (check que falla -> rojo; sin checks -> verde; separación de checks;
    sin _env avisa y no da verde falso).
